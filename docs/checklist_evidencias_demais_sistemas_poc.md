# Checklist de Evidencias - Demais Sistemas da Licitacao (PoC)

Objetivo:
- avaliar de forma objetiva o atingimento por sistema/plataforma na PoC.
- manter rastreabilidade direta com o TR do Municipio de Cambara.

Fonte oficial:
- `TR.pdf` (Processo Administrativo no 194/2026), secao "Definicao do Objeto" - LOTE I e LOTE II.

Como usar:
1. para cada sistema, marcar status (`Atingido`, `Parcial`, `Nao atingido`);
2. anexar evidencias tecnicas e funcionais;
3. registrar validacao do avaliador funcional.

Escala sugerida:
- `Atingido (100%)`: todos os criterios minimos atendidos com evidencias.
- `Parcial`: atendimento incompleto ou sem evidencias formais.
- `Nao atingido`: sem implementacao funcional comprovada.

## 2. Criterios Minimos de Evidencia (aplicar a cada sistema)

1. Acesso funcional:
- [ ] tela/menu do sistema acessivel;
- [ ] perfil com permissao adequada.

2. Fluxo principal:
- [ ] cenario ponta a ponta executado;
- [ ] resultado funcional comprovado (tela/relatorio/registro).

3. Auditoria e rastreabilidade:
- [ ] logs de autenticacao/operacao;
- [ ] usuario, data/hora e IP evidenciados.

4. Integracao e consistencia (quando aplicavel):
- [ ] reflexo em modulo relacionado;
- [ ] consistencia minima entre cadastros, movimento e relatorio.

5. Evidencia formal:
- [ ] captura/video;
- [ ] roteiro executado;
- [ ] aceite funcional registrado.

## 4. Criterio de Fechamento da PoC por Sistema

Considerar "Atingido (100%)" somente quando:
1. todos os criterios minimos da secao 2 estiverem concluidos;
2. houver evidencia objetiva anexada;
3. houver aceite funcional do avaliador.

Sem aceite e sem evidencia formal, classificar no maximo como "Parcial".
